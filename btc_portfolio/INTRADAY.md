# 장중 대응 모드 — 구현 완료, AWS 전략 전환 전

기존 `swing`은 30초 감시 / 알트 일봉 / 선물 4시간봉 전략이다. 이것은
장중 지표 변화에 수시로 진입하는 요구와 달랐다. `intraday`는 목표 5초 간격으로
현재 호가와 지표를 다시 평가한다. REST 조회 방식이며 네트워크·거래소 지연만큼
늦어질 수 있다. WebSocket 틱 단위·초단타 시스템이라고 표현하지 않는다.

## 실제 규칙

| 항목 | 동작 |
|---|---|
| 대상 | ETHBTC·BNBBTC·SOLBTC·XRPBTC 현물, BTCUSD_PERP COIN-M |
| 큰 추세 | 완료된 1시간봉 EMA20/50과 종가 |
| 진입 준비 | 완료된 5분봉 EMA9/21, RSI14, ATR14, 거래량 |
| 장중 진입 | 현재 매수/매도 호가가 최근 12개 완료 5분봉 고가/저가를 돌파할 때 평가 |
| 롱 조건 | 1시간 상승 추세, 5분 EMA9>21, RSI 50~75, 상방 돌파 |
| 숏 조건 | 1시간 하락 추세, 5분 EMA9<21, RSI 25~50, 하방 돌파. COIN-M만 숏 가능 |
| 유동성·비용 | 최근 완료 5분봉 거래량이 이전 20개 평균의 1.2배 이상, 스프레드 10bp 이하 |
| 변동폭 필터 | 2 ATR 손절폭이 2%를 넘으면 진입하지 않음. 해당 폭의 2배가 왕복 비용 가정의 3배 이상일 때만 진입 |
| 알트 선택 | 진입 조건이 맞고 BTC 대비 1·4시간 수익률 평균이 양수인 종목 중 1개 선택 |
| 손절 | 진입 시 2 ATR, 최소 0.3%. 현물은 프로그램 감시, 선물은 거래소 MARK_PRICE 보호 주문 |
| 익절·추세 청산 | 가격이 최초 손절폭의 2배만큼 유리하게 이동하거나 5분 EMA21/1시간 추세가 깨지면 청산 평가 |
| 최대 보유 | 4시간. 청산 주문이 체결돼야 실제 종료 |
| 재진입 | 청산 체결 후 해당 시장 15분 대기. 같은 날 재진입 가능. 같은 5분 구간의 중복 진입은 차단 |

RSI14는 최근 14개 변화의 상승·하락 합계 비율이며 Wilder 평활 RSI와 다르다.
거래량은 아직 완성되지 않은 봉의 값을 예측해 사용하지 않는다. 지표와 기준선은
완료 봉으로 계산하지만 **현재 호가의 돌파 판단은 봉이 끝나기 전에도 바뀐다**.
현물은 새 돌파 신호가 사라졌다는 이유만으로 즉시 매도하지 않는다. 보유 중에는
손절·익절·보유시간·추세 이탈 조건으로 관리한다.

비용 필터는 수수료·스프레드·슬리피지 가정에 비해 변동폭이 충분한지 확인하는
조건이다. 기대수익을 추정하거나 수익성을 보장하는 수치가 아니다. 횡보장에서는
장중에도 거래가 없을 수 있다. 뉴스/RSS/Gemini는 이 버전에 연결하지 않았다.

## 자금과 위험

기존 배정액(현물 0.0012 BTC, COIN-M 0.0018 BTC), 거래당 최대 0.5% 계획 위험,
일일 2% 신규 진입 차단, 최대 레버리지 3을 유지한다. 현물 한 종목 최대 배정은
현물 예산의 25%다. 선물 수량은 실제 진입·손절 가격의 역선물 손익과 비용으로
내림 계산한다. 1계약도 한도를 넘으면 진입하지 않는다. 손절폭이 좁아졌다고
레버리지나 위험예산을 자동으로 올리지 않는다.

익절의 2R은 가격 거리 기준이다. COIN-M의 실제 BTC 손익은 역수 가격식과
체결·수수료·펀딩에 따라 달라진다. 수량 위험예산 계산에는 기존 역선물 계산을 쓴다.

현물 손절은 소프트웨어 방식으로 API/서버 장애 때 지연될 수 있다. 주문 응답이
불명확하면 기존 원장 조회로만 해결하며 주문을 무작정 다시 보내지 않는다.

## 확인과 실행

```powershell
# 공개 시세를 사용한 판단: API 키·주문 없음. 비용은 보수적 가정임을 출력한다.
python -m btc_portfolio observe --config btc_portfolio/config.intraday.example.json

# 실계좌 및 기존 원장 확인: 주문 없음, 실제 수수료 사용
python -m btc_portfolio prepare --config btc_portfolio/config.intraday.example.json
```

`run`은 기존 실행 경로에 새 모드를 연결해 구현했으며 별도 명령의 확인 문자열이
있어야 주문을 보낸다. `--poll-seconds`를 생략하면 장중 모드는 5초, 기존 모드는
30초다. 메타데이터는 최대 5분, 실제 수수료는 최대 60초 캐시하며 호가는 매번
다시 가져온다. 거래소의 호출 제한 응답에는 최소 60초(차단은 최소 1시간) 대기한다.

**새 모드를 AWS에 자동 적용하지 않았다.** 현재 운영 원장은 기존 코드·전략에
묶여 있다. 기존 SOL 보유의 진입 시각·손절폭도 이전 원장에는 없을 수 있으므로,
배포 때 원장 백업·체결 대조·기존 포지션 인수 조건·새 코드 식별자의 명시적
이관이 필요하다. 원장을 삭제하거나 새 경로를 만들어 우회하지 않는다.

2026-09-25 확인: 기존 포트폴리오·현물·COIN-M 테스트와 신규 장중/응답 분할
회귀 검사를 합쳐 572개 통과. 공개 Binance 시세로 4개 알트/BTC와 BTCUSD_PERP의
5분/1시간 지표 계산을 완료했다(주문 0). 해당 표본에서는 비용 대비 변동폭 및
돌파 조건이 충족되지 않았다. 공개 관측의 수수료 가정은 실제 계좌 수수료와
다를 수 있으며, 실제 계좌 미리보기에서는 API로 수수료를 조회한다.

이전 일봉/4시간봉 백테스트 수익률은 장중 모드에 적용되지 않는다. 이번 확인은
장중 조건 변경, 중복 주문 방지, 당일 재진입, 비용·데이터 오류 차단과 공개 시세
연결에 대한 기능 확인이다. 장중 전략의 비용 차감 수익성은 아직 검증하지 않았다.

## 함께 수정한 시세 수신 결함

COIN-M 수신 코드가 `StreamReader.read(n)`을 한 번만 호출했다. 이 함수는
전체 응답이 아니라 현재 준비된 일부 데이터만 반환할 수 있어 큰 캔들 JSON이
잘릴 수 있다. 크기 상한을 유지하며 끝까지 청크를 모으도록 수정했다. 분할된
응답 재현 테스트를 추가했고, 잘못된 캔들은 구체적인 검증 오류로 거절한다.
이는 이전 AWS `TypeError`와 일치하는 가능한 원인이며, 당시 원본 응답을
보관하지 않아 그 사건의 원인으로 확정하지는 않는다.
