# BTC 수량을 목표로 다시 설계한 연구 시스템

목표는 **비용·미실현 손익·부채까지 반영한 순 BTC 자산의 증가**다.
기존 봇의 패턴, 1h/4h 조합, 고정 익절, 거래당 0.5% 수량 계산을 새 설계의 전제로 삼지 않는다.
연구·정보 모듈은 기존 매매 설정을 사용하지 않는다. PC 관측기는 기존의 OS 파일 잠금 유틸리티만 재사용한다.
이 폴더는 **연구·과거 COIN-M 종이관측·읽기 전용 계좌 점검**을 보존한다.
후속으로 선정한 현물 분할 모멘텀의 실제 주문 실행기는 **[`btc_spot`](../btc_spot/README.md)**에 있다.
현재 PC 실행과 실거래 준비는 그 문서와 `run_btc_spot.ps1`을 기준으로 한다.

현재 PC 실행과 실제 자본 재검증은 [실거래 준비 기록](PREPARATION_2026-09-24.md),
서버 구성은 [AWS 배포 안내](deploy/AWS.md)를 기준으로 확인한다.
실제 배정 예정액 0.003 BTC에서는 기존 0.007 BTC 연구 수익이 재현되지 않아 실거래 전환을 보류했다.

후속 [소액 거래 방식·수량 재검증](SMALL_CAPITAL_2026-09-24.md)에서 현물과 선물의 실제 최소 주문을 비교했다.
현물 분할 모멘텀은 같은0.003 BTC에서 전체 누적+38.18%(비용2배+17.46%)였으나 낙폭·미회복 기간도 컸다.
COIN-M 유지 구간 개선은 시작 자본에 민감했다. 이후 현물 실행기를 별도로 구현했으며,
아래 `btc_lab.pc` 명령은 과거 COIN-M 관측용으로 보존한다.

[공격형 포트폴리오 실제 규칙 재현](AGGRESSIVE_BACKTEST_2026-09-25.md)에서 알트 순환 전액 + COIN-M 50:50 조합은
5년 전체 수익이 알트 순환만(+495%)과 비슷하거나 낮았고, 낙폭과 최근 2년 성과에서 나았다. COIN-M 2배 단독은 타이밍에 극도로 민감했다.

[장중·스윙 전략 사전등록 탐색](STRATEGY_SEARCH_2026-09-25.md)에서 5분·15분·1시간 후보 72개는 검증 구간 플러스가 0개였고,
현재 장중 대응 모드는 두 구간 모두 크게 손실이었다. 비용을 넘은 후보는 4시간봉·일봉 추세와 일간 알트 순환뿐이었다.

[상황별 전략 전환 검증](REGIME_SWITCH_2026-09-26.md)에서 5분마다 상황(추세·변동성·테이커 흐름·OI·롱숏·펀딩)을 다시 판단해
롱·숏·대기를 바꾸는 방식을 시험했다. 36개 상황은 하루 171회 바뀌었지만 상황별 평균 우위가 비용보다 한 자릿수 작았다.
Gemini 리포트식 점수는 비용 전에도 예측력이 없었다. 매월 재학습 모델은 일관된 약한 예측력(IC 0.03~0.05)이 있었으나
현실적 지정가 체결에서 약 0%였다.
같은 모델을 swing 매매의 [체결 시점 조정](TIMING_OVERLAY_2026-09-26.md)에 쓰면 거래당 약 1~3bp 개선으로 사전 기준을 통과했다.
[상황 원장](LEDGER.md)은 이 예측과 거래소 실측 지표를 5분마다 기록·채점하고 매시 텔레그램으로 보낸다(주문 없음).
[2시간 예측 모델 개선 탐색](MODEL_SEARCH_2026-09-26.md)에서 호가창 깊이·다른 코인·긴 시간대 지표를 더하자 IC가 0.037에서 0.045로 올랐지만
사전 채택 기준(월별 개선 t>2, 앞·뒤 절반 모두 개선)을 통과하지 못했다. 비용과 레버리지 문턱(IC 약 0.15)에는 크게 못 미친다.

[BTC 포트폴리오 실행기 과거 재생](PORTFOLIO_BACKTEST_2026-09-25.md)은 `btc_portfolio`의 알트 순환·COIN-M 규칙을
2020-10 이후 시간봉으로 재생했다. BTC 기준 +43.38%(비용2배+19.65%), 최대낙폭10.55%였으나 이익이 소수 거래에 집중됐다.

최신 판단은 [일시 손실을 허용한 성장 연구](GROWTH_2026-09-24.md)에 있다.
사용자의 약50% 연구 낙폭 선호를 반영해 손실 연도를 허용하고 공격적인 모의연구 후보를 선정했다.
이전의 엄격한 구간별 선별 결과는 [재설계 보고서](REBUILD_2026-09-24.md)에 보존했다.

## 실행

저장소 루트에서 기존 Python 환경의 `numpy`, `pytest`를 사용한다.
가격차 스캐너는 Python 표준 라이브러리만 사용한다.

```powershell
# 현재 PC 관측 상태 (실주문 없음)
python -m btc_lab.pc status
python -m btc_lab.pc stop
python -m btc_lab.pc start

# 읽기 전용 실계좌 재점검 (기본 출력은 새 UTC 폴더)
python -m btc_lab.preflight --private

# 독립된 공식 RSS 정보 수집 (기본 Gemini 호출 없음)
python -m btc_lab.information --once --state-dir btc_lab/state/information

# 손실 구간을 허용한 최신 연구 (기본 출력: state/growth_20260924)
python -m btc_lab.growth_research

# 과거에 확보한 공개 CSV를 이용한 독립 연구
python -m btc_lab.research

# 공개 API에서 호가와 펀딩을 새로 관측해 UTC 시각별 폴더에 보존
python -m btc_lab.basis_scan

# 관련 전체 테스트
python -m pytest binance_coinm_v1/tests btc_lab/tests tests/test_basis_scan.py -q
```

기본 과거 입력은 `binance_coinm_v1/state/cache/`의 공개 데이터다.
다른 입력은 `--cache <폴더>`로 지정한다. 필요한 파일은 다음 네 개다.

- `BTCUSD_PERP_1h_contract.csv`
- `BTCUSD_PERP_1h_mark.csv`
- `BTCUSD_PERP_funding.csv`
- `exchange_info_BTCUSD_PERP.json`

기본 연구 출력은 `btc_lab/state/rebuild_20260924_v2/`다.
`protocol.json`에 후보·평가 기간·선택 규칙·원본/코드 SHA256을 먼저 저장한다.
소스나 데이터가 바뀌면 `--output <새 폴더>`를 사용해야 한다.
`report.json`, `comparison.md`, 각 후보의 BTC 평가곡선·체결·펀딩 원장을 저장한다.
최초 실행 폴더 `rebuild_20260924/`는 보완 이전 기록이며 v2 결과를 기준으로 읽는다.

스캐너는 `btc_lab/state/basis_<UTC시각>/`에 원본과 계산 결과를 저장한다.
명시한 `--output`에 이미 결과가 있으면 덮어쓰지 않는다.
폴더별 스냅샷은 단일 관측이며, 누적 거래 실적이나 실시간 종이 매매 성과가 아니다.

## 첫 재설계 연구의 규칙

종료된 UTC 일봉에서 방향과 변동성을 계산하고 다음 날 첫 시간봉 시가에 실행한다.
1시간봉은 체결·펀딩·보호 주문 평가에 사용한다.

- **지속 모멘텀:** 20/60/120일 수익률 부호의 평균으로 롱·숏 강도를 정한다.
- **채널 추세:** 이전 20일 범위를 종가로 돌파하면 보유하고 반대 10일 범위에서 해제한다.
- **지속 EMA:** EMA20/100의 상대 위치가 유지되는 동안 보유한다.
- **대조군:** 추세를 예측하지 않고 변동성에 맞춰 롱을 유지한다.

30일 변동성으로 목표노출을 조절하며, 목표 연환산 변동성 25%/40%, 진입 시 최대노출
0.75배/1.25배 두 수준을 비교한다. 변동성과 노출은 손실 한도가 아니다.
일중 가격 변화로 실제 노출이 진입 시 상한보다 커질 수 있다.
가격 기준 10% 손절을 사용하고 추가 진입으로 기존 손절을 느슨하게 만들지 않는다.
고정 익절이나 최대 보유기간은 두지 않는다.

개발 기간은 2021-04-01~2023-12-31, 확인 기간은 2024년,
최근 보고 구간은 2025-01-01~2026-09-24 09:00 UTC다. 각 기간은 0.007 BTC로 다시 시작한다.
개발 구간에서 기본/비용 두 배 모두 양수, BTC 최대낙폭 35% 이하, 청산·파산 없음인 후보 중
BTC CAGR이 가장 높은 하나를 선택하고 2024년에도 같은 조건을 확인한다.
최근 성과로 탈락 후보를 교체하지 않는다. 35%는 연구 선별 기준이며 사용자의 실계좌 손실 허용 승인이 아니다.
이번 여섯 후보는 개발 구간에서 모두 탈락했다.

## 회계와 해석 한계

역선물 BTC 손익은 `방향 × 계약수 × 계약USD / 진입가 - 방향 × 계약수 × 계약USD / 청산가`다.
모든 체결에 taker 비용·불리한 슬리피지·호가 단위 반올림을 적용한다.
기본 수수료 0.05%, 일반 슬리피지 3bp, 손절 10bp를 가정하고 이를 모두 두 배로 높인 경우도 다시 계산한다.
이전 연구에서는 계정 수수료를 조회한 값이 아니었다. 2026-09-24 준비 과정에서는 실제 taker 0.05%를 확인했다.
비용 변경으로 정수 계약 수와 이후 경로도 바뀐다.

펀딩은 공개 과거 이벤트를 사용한다. 같은 시간봉에서 펀딩과 손절의 순서를 모르는 경우
양의 펀딩 수입을 제외하고 음의 지급액은 유지하는 `adverse` 가정을 사용한다.
누락된 이벤트 mark는 해당 시간봉 시초 mark로 추정한다.
UTC 자정 평가액은 막 끝난 날·분기에 귀속한다. 미완성 마지막 시간봉은 거부한다.

유지증거금 1%, 청산 비용 0.5%는 연구용 가정이다.
공식 문서에서 무시하도록 한 `exchangeInfo.maintMarginPercent`를 실제 계정 한도로 사용하지 않는다.
이 엔진은 **공통 BTC 지갑** 모형이므로 기존 격리 계정의 실행 결과와 같다고 볼 수 없다.
낙폭은 시간봉 종가 평가 기준이며 봉 내부 낙폭, ADL, 장애, 실제 청산 호가를 재현하지 못한다.
이미 확인했던 역사 자료를 다시 사용했으므로 이번 결과를 완전히 새로운 표본 외 검증으로 표현하지 않는다.

가격차 스캐너는 두 계약의 실제 매수 ask·매도 bid와 깊이를 사용한다.
펀딩의 최근 평균 반복·현재 표시율 반복·0·음수, BTC 가격 변화, 출구 가격차, 수수료 두 배를 비교한다.
양쪽 포지션의 손익이 상쇄돼도 격리 증거금에서는 한쪽이 먼저 청산될 수 있다.
두 다리 동시 체결과 동일한 출구 가격은 보장되지 않는다.
