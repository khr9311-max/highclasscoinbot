실제 자본 규모에서 기존 연구 수익이 유지되지 않아 자금 이체·실주문·거래소 설정 변경은 실행하지 않았다.
AWS 리소스도 만들지 않았다.

실거래 시 0.003 BTC를 선물 지갑으로 옮기는 것은 **계획만** 작성했다. 현재 자금은 현물에 그대로 있다.

거래소에 남아 있는20배 설정을 봇이 사용하거나 변경한 적은 없다. 종이모형의 증거금 가정은3배다.

현재 API 화면의 Reading/Futures 체크는 유지하면 된다. 출금·자금 이동·현물/마진·기타 권한을 추가할 필요가 없다.
PC IP 제한을 유지하고, AWS로 실제 이전할 때 서버의 고정 EIP를 허용한다.
현재 공개 시세 관측기는 API 키 자체를 사용하지 않는다.

사용자의 총자산 기준 약50% 연구 선호와 비교할 때 이 두 기준을 섞지 않는다.
[소액 거래 방식·수량 재검증](SMALL_CAPITAL_2026-09-24.md)에 현물 대안과 전체계좌 결과를 추가했다.
종이관측 후보 명칭을 유지하는 것은
기존 연구 가설을 추적한다는 뜻이며 실거래 적합 판정이 아니다.

전체 공격형 기본모형에서2,003회 일별 목표 중1,424회는 최소 계약 미달이었다.

정수 모형에서 비용을 높였는데 손실이 줄어든 현상은 수량 경계와 이후 거래 경로가 달라진 결과다.
비용을 높이는 것이 유리하거나, 증액하면 안전하다는 의미가 아니다. 분수 모형의 낙폭도50%를 넘었다.

## 현재 PC에서 돌아가는 것

`btc_lab.pc`가 키 없는 `btc_lab.forward` 한 프로세스를 백그라운드로 실행한다.
상태는 `state/pc_momentum60/state.json`, 로그는 같은 폴더의 `observer.log`다.
시작액0.003 BTC, taker0.0005, 유지증거금률0.004, 후보`momentum60_stop20`이다.

```powershell
python -m btc_lab.pc status
python -m btc_lab.pc stop
python -m btc_lab.pc start
```

숨겨진 별도 창으로 실행하며 `stop`은 정상 종료 요청 파일을 보내 상태 저장 뒤 종료시킨다.
부팅 자동 시작·PC 절전 해제·장애 자동 재시작은 설정하지 않았다. PC가 켜져 있어야 관측한다.
오류가3회 연속 발생하면 종료하며, `status`로 실행 잠금과 최근 갱신 시각을 확인한다.

종이거래 시작 기준은 **2026-09-25 00:00 UTC = 한국시간09:00**다.
첫 완료 시간봉은 **한국시간10:00:30 이후 첫 갱신**부터 평가한다. 그 전에는 준비 일봉350개만 있고 거래0건이다.
시간봉이 끝난 뒤 시가 체결을 모형으로 재생하므로 실제 주문 지연·슬리피지·체결 품질의 증거가 아니다.
다운타임 후 누락 기간도 소급 재생한다. 서버 시간 지연30초, 실제 펀딩 지연·정정, 시간봉 내부 경로의 한계가 있다.

상태는 단일 원자적 파일로 저장하고 무결성·소스 해시·파라미터 일치를 검사한다.
후보나 소스를 바꾸면 기존 원장에 섞지 않는다. OS 잠금은 같은 PC의 동일 원장에 대한 중복 실행을 막는다.
PC와 AWS를 동시에 막는 분산 잠금은 아니므로 이전 시 PC를 먼저 정상 정지해야 한다.
파일 삭제·디스크 고장·전원 장애에 대한 완전 복구를 보장하지 않는다.

## AI와 정보

`information.py`는 매매 모듈과 연결되지 않은 정보 전용 경로다. 공식 Fed RSS 기사 제목·URL·발행 시각·
최초 관측·조회 시각을 보관하고, 만료 기사나 조회 실패 캐시를 최신 기사로 바꾸지 않는다.
Gemini 출력은 요약·사실·불확실성·출처만 허용하며 주문·수량·배율 필드를 거부한다.
내용은 사실 검증이 끝난 정보가 아니므로 매매에 자동 적용하지 않는다.

```powershell
python -m btc_lab.information --once --state-dir btc_lab/state/information
```

실제 공개 조회15건을 확인했으나 최신 발행일이9월16일이라 기본7일 사용기한을 넘었다.
따라서 사용 가능한 최신 정보 없음으로 기록했다. 현재 기본 수집원은 Fed 하나이며 종합 암호화폐 속보 서비스가 아니다.
Gemini API 실제 호출은 하지 않았고 상시 뉴스 작업도 시작하지 않았다.
기존 root `.env`를 읽지 않으며, 선택적 `--gemini --model MODEL_ID` 실행 때만 환경변수 `GEMINI_API_KEY`를 사용한다.

## 실거래까지 남은 구현과 검증

1. 실제 작은 자본과 계약 단위에서도 타당한 거래 방식·목표 비중을 다시 검증한다. 이번 결과로 증액을 권하지 않는다.
2. 새 일별 목표 포지션 실행기를 별도로 구현한다. 기존 V1의 Trendy 패턴·격리 증거금·익절 사다리 실행기와 교체 가능한 상태가 아니다.
3. 부분 체결·취소·일별 증감·반전·중복 요청·네트워크 단절·거래소 보호 주문·전체 계좌 재대조를 검증한다.
4. 공통 BTC 담보 연구 모형과 실제 cross/isolated 증거금·청산 조건을 일치시킨다. 기존 실거래 게이트를 낮춰 우회하지 않는다.
5. 목표변동성60%, 노출2배, 가격 손절20%와 실제 계좌 손실 한도를 구분해 확정한다. 약50% 연구 낙폭 응답은 실거래 손실 한도 승인이 아니다.

`capital_plan.json`의 향후 최초1계약 제안도 실행 승인이 아니다. 위 검증이 끝나기 전에는 이체나 주문에 사용하지 않는다.
옵션은 이번 배포에 구현·활성화하지 않았다. AWS는 [준비된 구성·설치·인계 문서](deploy/AWS.md)에 따라 PC 검증 후 진행한다.

서울 t3.small·20GB gp3·고정 공인IPv4 1개를 월730시간 사용하는 공식 단가 합계는 약24.45달러다.
부가세·트래픽·추가 CPU 크레딧·백업은 별도다. 조회 BTC 가격 기준 약0.000293 BTC/월로
운용 검토액0.003 BTC의약9.8%에 해당한다. 현재 규모에서는 PC 관측을 더 이어가는 편이 경제적이다.
단가 원본과 계산 근거는 AWS 문서 및 `deploy/aws-prices-seoul-2026-09-24.json`에 보존했다.
