# 작은 자본의 거래 방식과 수량 재검증

**현재 규모에서는 BTC/USDT 현물이 수량 조절에 가장 적합하다. 다음 연구 우선순위는 현물 분할 모멘텀이다.**
BTC 선물의 배율을 올려도 최소 계약 단위는 작아지지 않는다. COIN-M 유지 구간 방식은 일부 개선됐지만
시작 자본을10%만 바꿔도 장기 성과가 뒤집혀 현재 금액에 맞춘 안정적인 해법으로 보기 어렵다.

이번에는 주문 수량 계산과 별도 연구 엔진을 구현·검증했다. 실주문·이체·API 권한 변경은 하지 않았다.
기존 PC 종이관측은 기존 설정으로 계속 실행하며, 새 연구 결과로 자동 교체하지 않았다.

## 실제 주문 단위와 계정 수수료

운용 검토액0.003 BTC, 예비분0.00112273 BTC, 합계0.00412273 BTC를 구분했다.
2026-09-24 12:52~12:53 UTC 공개 호가·계약 사양·referencePrice를 조회했다.
금액과 비율은 당시 시세 기준이며 실제 주문 수락을 보장하는 값이 아니다.

| 방식 | 최소 시장가 신규 주문 | 수량 증분 | 최소 명목 노출 / 운용액 |
|---|---:|---:|---:|
| BTC/USDT 현물 | 0.00006 BTC ≈ 5.01 USDT | 0.00001 BTC | 약2.0% |
| BTC/USDC 현물 | 0.00006 BTC ≈ 5.01 USDC | 0.00001 BTC | 약2.0% |
| BTC USDⓈ-M 무기한 | 0.001 BTC ≈ 83.45 USDT | 0.001 BTC | 약33.4% |
| BTC COIN-M 무기한 | 1계약 = 100 USD | 1계약 | 약40.0% |

USDⓈ-M의 현재 최소명목 필터는50이지만, 최소수량0.001 BTC가 현재 가격에서 더 큰 제한이다.
이 비율은 **명목 노출**이며 증거금 비율이 아니다. 배율은 증거금을 바꾸지만 최소 수량을 줄이지 않는다.
USDⓈ-M에는 BTC를 담보 통화로 바꾸는 비용도 포함해 수량 적합성을 계산했다. 별도의 USDⓈ-M 수익 연구는 하지 않았다.
USDT·USDC·USD는 동일 통화로 보장되지 않으며 각 상품의 실제 호가를 사용했다.

계좌를 GET으로 조회한 현물 기본 taker 수수료는 BTCUSDT0.10%, BTCUSDC0.095%다.
BNB 할인 설정은 켜져 있지만 조회한 지갑에 BNB가 없으므로 할인을 적용하지 않았다.
선물 수수료는 앞서 확인한 COIN-M taker0.05%를 사용했다. USDⓈ-M 수수료는 수량 비교용 가정이며 별도 확인값이 아니다.

현물 수량 계산은 다음을 반영했다.

- Decimal로 수량 단위를 정확히 내린다. 작은 목표 주문을 최소금액에 맞추려고 확대하지 않는다.
- LOT_SIZE와 활성 MARKET_LOT_SIZE의 교집합을 적용한다. 시장가 필드가0이면 기본 LOT_SIZE를 따른다.
- MIN_NOTIONAL/NOTIONAL의 시장가 적용 여부와 최대 수량·금액을 확인한다.
- 현재 referencePrice가 있으면 우선하고, 없으면 해당 평균가격을 사용한다. 모형에는 과거 시가를 대용한다.
- 매수 수수료는 받은 BTC에서, 매도 수수료는 받은 USDT에서 차감한다.
- 가용 BTC와 현금 범위 안에서만 주문한다. 예비 BTC·차입·증액을 사용하지 않는다.
- 최종 환전이 여러 주문을 요구하면 상한을 지켜 반복한다. 주문 가능한 미환전 잔액과 거래 불가능한 잔돈을 구분한다.

현재 호가의 단순 검산에서, BTC 비중을100%→99%로 줄이는 주문은 최소금액 미달로 건너뛴다.
100%→50% 예시는0.00150 BTC 매도, 비용 후 약125.0383 USDT 수취로 계산됐다. 실제 주문은 아니다.
예시는 `state/market_fit_20260924/sizing_examples.json`에 있다.

공식 근거: [현물 필터](https://developers.binance.com/en/docs/products/spot/filters),
[수수료 부과 자산](https://developers.binance.com/en/docs/products/spot/faqs/commission_faq),
[USDⓈ-M 시장 사양](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/market-data).

## 현물 분할 모멘텀의 의미

20·60·120일 수익률의 부호를 평균하고 `(1 + 평균 부호) / 2`를 BTC 목표 비중으로 사용한다.
일반적으로0%, 33.3%, 66.7%, 100%로 움직인다. 수익률이 정확히0인 투표가 있으면 중간 비중도 가능하다.
완료된 일봉으로 결정하고 다음 UTC 일봉 시가에만 모형 주문을 낸다.
BTC가 약해질 때 일부를 USDT로 보유하고, 다시 전환할 때 BTC 수량이 늘어날 가능성을 검증한 것이다.

| 현물 분할 모멘텀 | 기본 비용 | 비용2배 |
|---|---:|---:|
| 2024년까지 별도 계좌 수익 | +25.09% | +12.21% |
| 2025년부터0.003 BTC로 재시작 | +10.35% | +4.55% |
| 전체 기간 연속 계좌 수익 | +38.18% | +17.46% |

전체 연속 계좌의 최종 자산은 **실제 보유0.00413904 BTC + 0.521834 USDT**다.
USDT 평가까지 합치면0.00414528 BTC다. 잔여 USDT를 이미 보유한 BTC로 표시하지 않았다.
예비분까지 합친 전체 순자산은0.00526801 BTC 상당이며, 실제 BTC 보유는0.00526177 BTC다.
전체계좌 수익은+27.78%, 연환산 약4.57%다. 운용 부분 연환산은약6.08%다.

최악의12개월은-27.55%, 고점에서 회복하지 못한 최장 기간은**1,558.5일**이었다.
양의 누적 수익이 있어도 빠른 회복이나 빠른 BTC 증식을 입증하지는 못했다.
비중5% 유지 구간은 이 역사에서 차이가 작았으므로 그 작은 차이를 최적 매개변수의 증거로 쓰지 않는다.

현물도 같은 ±10% 자본 민감도 검산을 추가했다. 분할 모멘텀을 바꾸지 않고 전체·최근 두 기간과
기본·비용2배를8회 비교했다. 이미 결과를 본 뒤의 진단이며 독립된 미래 검증이나 금액 최적화가 아니다.

## COIN-M 개선안의 추가 검산

신호·노출·가격 손절은 그대로 두고, 목표가 기존 수량에서0.5계약 이내로 바뀌면 기존 수량을 유지했다.
목표0·반전·손절은 즉시 처리하고, 일별 결정 시 비용 반영 후 노출·증거금 상한이 우선한다.
결정 이후 가격이 움직이면 노출이2배를 넘을 수 있다. 이번 시간봉 평가의 최대치는2.5143배였다.

별도 사후 검산에서 새 비용·상한 처리만 적용하고 유지 구간을 껐을 때 원본4개 결과와 원장 전체가 같았다.
따라서 이번 자료에서 개선은 상한 처리만으로 설명되지 않았다. 수수료가 항상 줄어든 것도 아니다.

양수였던0.003 BTC 주변의 자본을 ±10% 바꾸는 사후 민감도 검산도 수행했다. 좋은 금액을 찾는 최적화가 아니다.

| 초기 운용 BTC | 전체 기본 수익 | 전체 비용2배 수익 | 기본 최대낙폭 |
|---|---:|---:|---:|
| 0.0027 | -22.13% | +19.20% | 57.65% |
| 0.0030 | +9.82% | +6.97% | 43.71% |
| 0.0033 | +0.63% | -3.12% | 47.67% |

수량 경계 때문에 비용·초기 잔액의 작은 변화가 이후 거래 경로를 바꾼다. 비용을 높이거나
특정 잔액을 맞추면 수익이 좋아진다고 해석하지 않는다. COIN-M 개선안은 이번 규모의 기본 운용 방식으로 권하지 않는다.

## 적용 범위와 남은 일

구현 파일은 `market_fit.py`, `small_data.py`, `small_coinm.py`, `small_spot.py`,
`small_sensitivity.py`, `small_spot_sensitivity.py`, `small_capital_report.py`다. 실주문 실행기는 포함하지 않는다.
기존 PC 관측기의 소스 해시와 설정은 유지했다. 현재 API의 현물 거래 권한도 바꾸지 않았다.

다음 연구는 새 현물 모형을 별도의 종이 원장으로 관측하는 것이 합리적이다. 주문 권한·실거래 실행기는
별도로 검증해야 하며, 이번 연구 수익만으로 실거래 준비 완료라고 판단하지 않는다.
약250달러 규모에서는 AWS 상시 비용도 큰 비중이므로 PC 관측을 먼저 유지한다.

현물 입력은53,616개 완료 시간봉과2,235개 완료 일봉이다. API 시간봉20개 누락과6개 조기 종료 기록은
따로 보존하고 보간하지 않았다. 본 실험 구간에서는16시간이 빠졌으나 일별 주문 예정 시각과 겹치지 않았다.
일봉 신호는 거래소가 제공한 실제 일봉으로 계산했다. 누락 구간·장중 극값은 낙폭 계산의 한계다.
과거 호가 깊이, referencePrice, 수수료 등급, 거래 필터 변화, 체결 지연을 완전히 재현하지 못했다.

## 재현과 산출물

아래 출력 폴더의 기존 결과를 보존하므로 다시 비교할 때는 새 이름을 지정한다.

```powershell
# 현재 공개 사양과 수량 적합성; 현물 수수료는 확인한 값을 명시
python -m btc_lab.market_fit --output btc_lab/state/market_fit_NEW --usdt-fee 0.001 --usdc-fee 0.00095

# 공개 현물 자료: 누락·조기 종료 기록과 데이터 해시 보존
python -m btc_lab.small_data

# 3개 COIN-M 수량 정책의 고정12회 비교
python -m btc_lab.small_coinm --output btc_lab/state/small_coinm_NEW

# 4개 현물 규칙의 고정24회 비교
python -m btc_lab.small_spot --output btc_lab/state/small_spot_NEW

# 예비 BTC를 포함한 전체계좌 평가
python -m btc_lab.small_capital_report --output btc_lab/state/small_capital_comparison_NEW

# 사후 자본 민감도 검산 (성과가 좋은 자금 크기를 고르는 최적화가 아님)
python -m btc_lab.small_sensitivity --output btc_lab/state/small_sensitivity_NEW
python -m btc_lab.small_spot_sensitivity --output btc_lab/state/small_spot_sensitivity_NEW

# 기존 관측 상태
python -m btc_lab.pc status
```

연구 원장은 `state/small_coinm_20260924/`, `state/small_spot_20260924/`,
합산 보고서는 `state/small_capital_comparison_20260924/`다.
COIN-M 자본 민감도는 `state/small_sensitivity_20260924/`,
현물 자본 민감도는 `state/small_spot_sensitivity_20260924/`,
guard 단독 검산은 `state/small_coinm_20260924/diagnostics/`에 있다.
실계정 수수료의 제한된 조회 결과는 `state/small_capital_market/spot_commissions.json`에 저장했다.
이 폴더들은 git 제외 대상이며 API 키·시크릿은 기록하지 않았다.

잔액 보존, 미래 참조 방지, 최종 환전·잔돈 구분, 예약 시각 누락 처리, 공개 GET 전용 경계를 확인했다.
