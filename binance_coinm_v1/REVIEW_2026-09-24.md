| 검증 기준 변경, NaN/Infinity, 미래 생성 시각 등이 잘못 승인될 여지 | 수치·범위 검사, 검증 정책/리포트 버전 확인, 미래/비정상 시각 거부. 기존 리포트 재사용 차단 |
| 마크가만 계속 오면 오래된 체결가도 신선하다고 판단 | 체결가·마크가별 시각 검사, 지연/역순 가격 거부 |

| 백테스트 시간봉/진입 트리거 설정을 바꿔도 기존 데이터·판정으로 리포트 생성 | 지원하지 않는 설정 거부 및 데이터 심볼/시간봉 일치 검사 |

## 사용자가 알아야 할 변경

- 전략 버전은 `trendy_kangaroo-v1.1`, 검증 리포트 형식은 버전 2다. 기존 검증 리포트는
  재검증해야 한다. 위험 설정 또는 검증 기준 변경 후에도 재검증이 필요하다.
- 과거 paper 거래는 삭제하지 않는다. 다만 지문/시장 환경 기록이 없으면 현재 전략의
  검증 표본으로 인정하지 않는다. 이 변경 이후 생성한 일치 표본을 사용한다.
- 백테스트는 현재 1h/4h, CONTRACT_PRICE 진입, STOP_PRICE_PROTECT=false만 검증한다.
  그 외 설정은 잘못된 검증 리포트를 만들지 않도록 오류로 중단한다.
- 필수 작업이 죽으면 봇은 알림을 남기고 오류 종료한다. 자동 재시작 서비스 설치는
  이번 작업에 포함하지 않았다.

## 아직 실거래 검증이 필요한 부분

1. **전략 수익성 및 실제 거래소 통합:** 테스트넷의 실제 조건부 주문 발동, 동시
   closePosition 허용, 부분 체결, 취소 경합을 계정 연결 없이 확정할 수는 없다.
2. **회계의 추가 한계:** `sync_funding`은 과거 펀딩을 수집할 때 현재 가격으로 USD를
   환산한다. 그러므로 모든 USD 항목이 사건 당시 가격이라는 기존 설명은 펀딩에
   대해서는 정확하지 않다. 체결/펀딩 REST 조회의 페이지네이션과 누락 후 재귀속,
   수수료가 BTC가 아닌 경우도 별도 보강·검증 대상이다.
3. **장기 운영:** paper 계좌 스냅샷은 약 10초 간격이므로 강제 종료 시 주문 DB와의
   원자적 복원은 보장되지 않는다. 다중 프로세스 동시 실행 방지, 장애 주입을 통한
   강제 종료 시험, 서버 감시·자동 재시작 설정도 후속 운영 작업이다.
4. **모델 가정:** 시간봉 내부 체결 순서·마크 트리거의 실제 시장가 체결 가격·슬리피지는
   근사다. 마크 데이터 누락 대체, 입출금 미보정 일손실 한도도 고려해야 한다.

따라서 이번 수정은 확인된 실행/검증 결함 보완이며 실거래 준비 완료 판정이 아니다.
수익성을 얻기 위해 이번 결과에 맞춰 전략 파라미터를 최적화하지 않았다.

## 공식 문서 대조

조건부 주문을 별도 algo 엔드포인트로 보내는 처리, 주문 응답의 avgPrice 제거와 조회로
체결가 확인, UM/CM 포지션 모드 공유는 공식 통합 안내와 일치한다.
[Binance COIN-M/UM 통합 안내](https://developers.binance.com/en/docs/products/derivatives-trading-coin-futures/Important-CM-UM-Integration-Notice)

algo 조회의 actualQty/actualPrice는 부분 체결도 나타낼 수 있어, 주문 종료 상태만으로
TP 계획 수량 전부를 청산했다고 간주하지 않도록 수정했다.
[Binance 공식 Algo Order API](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/trade)
