### 전략 모드 (`STRATEGY_MODE`)

| 값 | 주문을 내는 경로 | LLM 판정 |
|---|---|---|
| `naked` (기본) | 가격행동 패턴 (아래 절) | 기록만 + 뉴스 점수는 거부권 |
| `llm` | 아래 의사결정 흐름 | 주문 |

두 경로가 같은 종목에 동시에 주문하면 포지션이 엉키므로(가격행동 손절이 LLM
매수분까지 판다) 한쪽만 주문한다.

### 의사결정 흐름 (`STRATEGY_MODE=llm`)

```
웹소켓 → MarketState(특징벡터) → 서킷브레이커 → 리스크 회계
                                        ↓ (통과 시)
      Crypto Agent 점수 ┐
                        ├→ decide_action(0.7c + 0.3n) → RL 확인 → 메타라벨 필터
      News Agent 점수   ┘                                    ↓
                                          RiskManager 최종 관문 → 주문
```

**모든 관문을 통과해야만 주문이 나간다.** 어느 한 단계라도 실패하면 그 주기는 건너뛴다.

최종 BUY/SELL/HOLD 판정은 LLM 이 문장으로 고르지 않는다. LLM 은 crypto/news
점수만 내고, 조합과 판정은 `multi_agent.decide_action()` 이 숫자로 한다
(`|0.7*crypto + 0.3*news| >= MIN_ENTRY_SCORE`). 프롬프트로 판정을 맡겼을 때
실측 59건이 전부 HOLD 로 나왔고(그중 41%는 두 점수의 부호가 일치했다),
근거 문장이 자기 점수 체계를 어기는 사례가 반복돼서 코드로 옮겼다.

### 섀도 모드

`SHADOW_MODE=true`(기본)면 `TARGET_TICKERS` 전체를 판정·기록하되 **주문은
첫 종목(`TARGET_TICKERS[0]`)에만** 낸다. 메타모델은 BUY/SELL 표본 300건이
있어야 학습되는데, 한 종목만 쓰면 실측 4.5건/시간이라 약 3일이 걸린다.
`meta_trainer` 는 라벨을 주문 체결 여부가 아니라 기록된 가격 시계열의
삼중장벽으로 만들기 때문에, 주문을 내지 않아도 표본이 된다.

> 섀도 신호에는 슬리피지·부분체결이 없어 실제보다 낙관적이다. 특히 호가가
> 얇은 종목에서 차이가 크므로, 실매매 확장 판단 시 그만큼 할인해서 읽어야 한다.

## 📐 가격행동 전략 (Naked Forex)

> 설계 근거, 최종 검증에서 찾아 고친 문제 21건, 백테스트 세부, 남은 한계는
> [docs/NAKED_FOREX.md](docs/NAKED_FOREX.md) 에 모아 두었다.

Nekritin & Peters, *Naked Forex* (2012) 의 규칙을 업비트 현물로 옮긴 것.
책의 매매는 세 단계다: **존을 찾고 → 가격이 존에 닿기를 기다리고 → 존에서
촉매 패턴이 찍히면 진입.**

```
봉 마감(1시간봉) → 4시간봉 존 → 패턴 판정 ─┬→ 종이 매매 (모든 신호 × 청산 4종)
                                         └→ 라이브 패턴이면: 뉴스 거부권 → 메타 → 매수스톱 대기
                                                                  ↓ (틱으로 돌파 확인)
                          시장가 매수 → 손절(꼬리 아래) / 목표(다음 존) / 추적 → 시장가 매도
```

| 책 | 코드 | 비고 |
|---|---|---|
| 4장 존 | `find_zones` | 4시간봉 **종가**의 꺾임 3회 이상, 0.5 ATR 을 한 구간으로. 극단 고저점은 1회도 인정 |
| 5장 라스트 키스 | `last_kiss` | 박스(2+2 터치) 돌파 후 상단 되돌림 양봉. 종가가 박스 안이면 즉시 청산 |
| 6장 빅 섀도 | `big_shadow` | 감싸기 + 종가 위쪽 25% + 직전 5봉 최대 + 왼쪽 여백 7봉 |
| 7장 와미/물라 | `wammie` | 이중바닥, 두 번째 저점이 더 높고 6봉 이상 간격. 손절은 첫 저점 아래 |
| 8장 캥거루 꼬리 | `kangaroo_tail` | 시가·종가 위쪽 1/3, 직전 봉 범위 안, 직전 3봉보다 큼, 1 ATR 이상 |
| 9장 빅 벨트 | — | **제외.** 주말 갭 전제인데 코인은 24시간이라 갭이 없다 |
| 10장 추세 캥거루 | `trendy_kangaroo` | 40봉 추세(3 ATR, R² 0.5) 중 3~10봉 쉬어가기, 꼬리가 쉬어가기 저점 아래로 |
| 11장 청산 | `Trade` | zone(존 없으면 3봉 추적) / split / ladder / three_bar |
| 13장 반대 신호 | `EXIT_ONLY` | 저항 존의 약세 캥거루·빅섀도·물라가 나오면 보유분 청산 |

현물이라 공매도가 없다. 매수 패턴만 진입, 매도 패턴은 청산 신호로만 쓴다.
진입은 전부 **매수스톱**(신호 봉 고가 돌파 시)이고, 돌파 전에 손절선부터
닿으면 신호를 버린다. 사이징은 고정 위험(`NAKED_RISK_PER_TRADE_KRW`, 손절 시
잃는 금액)이고, 신호의 진입가가 아니라 **실제 매수 시점 가격**으로 잰다 (갭으로
비싸게 사면 금액을 줄인다).

### 알트코인

"급등을 쫓는" 방식은 넣지 않았다. 책도 돌파 대부분을 가짜 돌파로 보고,
업비트 급등 알트 상당수는 '주의' 지정 펌프다. 대신:

- **유니버스** (`AltUniverse`): KRW 마켓 24시간 거래대금 50억 이상 상위 20,
  업비트 유의·경고·주의(가격 급변·거래량 급증·입금 급증·해외 괴리·소수계정 집중)
  제외, 스테이블 제외, 스프레드 0.2% 이하. 6시간마다 갱신.
- **진입**: 급등 후 첫 쉬어가기(추세 캥거루)·첫 되돌림(라스트 키스)만.
- **청산**: 신고가 부근은 위에 존이 없어 목표가를 못 정하므로 추적(ladder/3봉).
- **라이브**: 알트 신호가 라이브 패턴이면 그 종목만 그때 웹소켓 구독
  (`ExecutionEngine.watch`)해서 매수스톱을 감시하고, 거래가 끝나면 구독을 푼다.
  코어와 같은 리스크 한도(종목당·전체 노출·일손실)를 탄다.

### 검증과 실주문 게이트

봇이 **스스로 검증한다** (`NAKED_AUTO_VALIDATE`, 기본 켬): 기동 시와 하루에 한 번
백테스트 거래 + 그때까지 쌓인 표본 외 종이 매매를 합쳐 재평가하고, 백테스트가
30일(`NAKED_BACKTEST_REFRESH_DAYS`)보다 오래됐거나 결과를 바꾸는 설정(패턴·손익비·
유효 봉 수·보유 기한·봉 단위·존 봉 수)이 바뀌었으면 백그라운드에서
새로 돌린다 (약 5분). 캔들 요청은 초당 3회로 제한해 라이브 스캔(초당 6회)과 합쳐도
업비트 시세 한도(초당 10회)를 넘지 않는다. 손으로 돌리는 건 확인용이다:

```bash
python validate_naked.py backtest --days 180 --alts 20   # 과거 캔들로 검증 (약 5분)
python validate_naked.py report                          # 백테스트 + 운영 종이매매 합쳐 재평가
# 서버에서는 봇과 같은 상태 폴더를 봐야 한다: --state-dir /var/lib/coinbot
```

`state/naked_validation.json` 에 결과를 쓰고, **실주문 모드**(`DRY_RUN=false`)
에서는 이 파일이 통과여야 가격행동 주문을 낸다. 통과 기준:

- 라이브 설정(패턴 × 청산) 거래 100건 이상, 비용 후 평균 > 0
- DSR ≥ 0.95 (시행 수 = 비교한 조합 전부), PBO ≤ 0.5
- **표본 외 종이 매매 30건 이상, 평균 > 0**
- 리포트가 **지금의 라이브 설정**(청산방식·라이브 패턴)을 평가한 것일 것.
  설정을 바꾸면 다음 재평가 전까지 게이트가 닫힌다
- 리포트가 3일 이내 (`NAKED_VALIDATION_MAX_AGE_DAYS`). 매일 새로 쓰이므로 이게
  지났다는 건 자동 검증이 며칠째 실패한다는 뜻이다. 자동 검증을 끄면 직접
  `report` 를 돌리거나 이 값을 늘려야 한다.

게이트는 매일 재평가로 **닫히기도, 다시 열리기도** 한다 (바뀔 때 텔레그램 알림).
닫히면 대기 중인 매수스톱만 취소하고, 이미 보유 중인 거래는 손절·목표·기한까지
정상 관리한다. 종이 매매와 기록은 계속된다. `NAKED_LIVE=false` 처럼 설정에서 끈
것은 게이트가 켜지 않는다. DRY-RUN 에서는 게이트 없이 모의 주문까지 탄다.

**종이 장부와 평가의 표본 일치.** 종이 장부는 종목 × 청산방식 × 패턴마다 거래를
하나씩 굴린다 (패턴끼리는 막지 않는다 - 막으면 다른 패턴 종이 거래 때문에 라이브
패턴의 신호가 빠져, 실제 운용과 다른 표본이 된다). 여러 패턴을 함께 라이브로 쓰는
조합을 평가할 때는 `non_overlap` 이 라이브의 '종목당 1거래' 규칙을 적용한다.

운영 중 기록: `state/naked/signals/*.jsonl`(모든 신호), `state/naked/trades/*.jsonl`
(종이·라이브 거래 결과, 비용 후 수익률·R), `state/naked/state.json`(재시작 복원).
가격행동 전용 메타 모델(`naked_meta_model.pkl`)은 이 거래들로 매시간 재학습하고,
CV AUC 0.55 이상일 때만 필터로 쓴다 (2026-09-24 백테스트 표본 기준 0.54 라 미사용).

미보유 종목 매도 차단, 재시작 시 미체결 주문 복구가 항상 작동한다.

> 일일 건수 상한을 매수에만 거는 이유: 예전에는 매수·매도가 상한을 공유해서,
> 상한을 다 쓰면 급락 중에 보유분을 청산하지도 못하는 상태가 됐다.

### 서킷 브레이커

조건 중 **하나만 걸려도** 거래를 차단하고 미체결 주문을 전량 취소한다 (60초 쿨다운).

| 조건 | 기본 상태 | 판정 |
|---|---|---|
| **점성 게이트** | ✅ 활성 | 스프레드 확대 + 호가 불균형 + 실현변동성을 0~1 로 결합, `z > 0.8` |
| **곡률 붕괴** | ❌ 비활성 | `kappa < -0.3` (`curvature_enabled=True` 로 켬) |
| **호가창 단절** | ❌ 비활성 | Betti-0 가 이력 중앙값+8 을 10틱 연속 초과 (`topology_enabled=True` 로 켬) |

**곡률과 위상은 지표가 의도대로 동작하지 않아 기본 비활성이다.** 임계값을 높여
증상을 가리는 대신 껐고, 재설계 전까지 이 상태를 유지한다. 두 지표의 값은
계속 기록되므로(가격 CSV 의 `betti0`/`kappa` 컬럼, `depth/*.jsonl`) 재설계용
데이터는 끊기지 않는다.

> **위상(Betti-0)** — 감지하려는 사건에 역방향으로 반응한다. 실측 BTC 사다리
> (60단계)에서 호가를 취소해가며 측정하면 취소 0%/40%/60%/80%/95% 에서
> Betti-0 가 7/6/5/3/1 로 **내려간다**. 호가창이 95% 증발한 상태가 '완벽히
> 연결된 정상 호가창'으로 판정된다. 갭을 같은 스냅샷의 중앙값 갭으로
> 정규화하기 때문에, 호가가 사라지면 모든 갭이 같이 커져 비율이 유지되고
> 셀 수 있는 갭 자체가 없어진다. 이 조건으로 발동한 것은 전부 노이즈였다
> (프로덕션 실측 분포: 중앙값 7 / p90 13 / p99 16 / 최대 19, 자기상관 lag1 0.82).
>
> **곡률(kappa)** — '위험'이 아니라 '한산함'을 잰다. 표준화된 피처 상관행렬의
> 스펙트럼 엔트로피라, 값이 낮다는 것은 피처가 한 방향으로 몰렸다 = 호가가
> 얇고 거래가 뜸하다는 뜻이다. 실측 음수 비율은 BTC 2.5% / ETH 10.1% /
> XRP 37.5% / SOL 49.2% 로, 얇은 종목일수록 상시 음수에 가깝다.
>
> 재설계한다면 연결성분이 아니라 **단계 개수 / 총 잔량 / 가격 스팬**을 직접
> 보는 쪽이어야 한다. 그때까지는 `z_t` 가 이 역할을 한다 — `rel_spread` 가
> 들어 있어 호가가 증발하면 스프레드 확대로 반응한다.

## 🚧 알려진 한계

구현되지 않았거나 의도대로 동작하지 않는 것들. 실전 투입 전 반드시 확인할 것.

- **LLM 경로(`STRATEGY_MODE=llm`)에는 손절/익절이 없다.** 그 경로에서
  `place_market_sell` 은 판정 규칙이 SELL 을 낼 때만 불린다.
  가격행동 경로(기본)는 모든 거래에 구조적 손절·목표·보유기한이 있다.
  `DAILY_LOSS_LIMIT_KRW` 는 신규 매수만 막고 보유분을 강제 청산하지 않는다.
- **가격행동 전략의 엣지는 확인되지 않았다.** 책 규칙 그대로는 백테스트에서
  음수였고, 라이브 기본값(추세 캥거루)은 사후 선택이라 표본 외 검증 전이다.
  위 '검증과 실주문 게이트' 절 참고.
- **가격행동 청산은 틱 가격(웹소켓 최신 체결가)으로 판정해 시장가로 판다.**
  손절선을 뚫고 급락하는 순간에는 손절가보다 불리하게 체결된다.
- **곡률·위상 지표가 비활성이다.** 사유는 위 서킷 브레이커 절 참고.
  현재 살아 있는 차단 조건은 점성 게이트 하나뿐이다.
- **수익성이 검증되지 않았다.** 메타모델 학습 전까지는 모든 진입이 검증되지
  않은 신호다. 시장가 주문이라 왕복 약 0.12%(수수료 0.05%x2 + 스프레드)의
  마찰비용이 확정적으로 나가며, 전략은 최소한 이를 넘어야 본전이다.
- **서킷 브레이커는 `TARGET_TICKERS[0]` 기준으로만 판정한다.** 종목별 평가로
  확장할 경우 곡률을 켜서는 안 된다(얇은 종목은 상시 음수).
- **LLM 경로 매도에는 60초 재주문 쿨다운이 적용된다.** 가격행동 청산은
  `urgent=True` 로 쿨다운을 건너뛴다(보유량·최소금액 검증은 그대로).
- **가격행동 손절은 거래소 주문이 아니라 봇이 감시한다.** 업비트 현물에 스톱
  주문이 없어서다. 봇이 멈추거나 웹소켓 시세가 정체되면(30초) 그동안 손절이
  나가지 않는다. 재시작하면 `state/naked/state.json` 에서 복원해 이어서 관리한다.
- **라이브 거래 기록의 체결가는 주문 직전 최신 체결가다.** 실제 평균 체결가
  (슬리피지 포함)가 아니므로 라이브 수익률은 약간 낙관적이다. 매도 수량도
  추정치라 엔진이 보유량으로 자른다.
- **뉴스 거부권은 코어 4종목에만 걸린다.** 뉴스 점수는 LLM 판정 경로에서 나오는데
  그 경로는 `TARGET_TICKERS` 만 돈다. 알트(백테스트상 라이브 거래의 대부분)는
  뉴스 필터 없이 들어간다. 알트까지 LLM 을 부르면 호출 비용이 6배가 된다.
- **표본 외 종이 매매 30건은 이 전략에 약한 증거다.** 승률 27%에 수익이 큰 승리
  몇 건에 몰린 분포라, 30건 평균은 운에 따라 크게 흔들린다. 게이트의 실질적인
  관문은 백테스트+종이 매매 전체의 DSR·PBO 다.
- **LLM 시절부터 들고 있던 코어 코인 보유분은 가격행동 전략이 관리하지 않는다.**
  가격행동은 자기가 산 거래만 손절·청산한다.
- **알트 백테스트에는 생존자 편향이 있다.** 유니버스를 '지금' 거래대금 상위로
  고르므로 그 사이 상장폐지·거래 고갈된 종목이 빠져 있다.
- **`STRATEGY_MODE=naked` 에서도 LLM(Gemini) 판정은 계속 호출된다.** 주문은
  내지 않지만 가격행동의 뉴스 거부권이 이 판정의 뉴스 점수를 쓰고, 기록도 남긴다.
  API 비용을 줄이려면 `config.py` 의 `LLM_INTERVAL_SEC`(기본 300초)를 늘린다.
