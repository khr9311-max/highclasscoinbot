# 가격행동(Naked Forex) 전략 — 설계·검증 기록

작성 2026-09-24. Nekritin & Peters, *Naked Forex* (2012)의 가격행동 규칙을 업비트
현물 봇에 넣은 작업의 전체 기록이다. 운영 설명은 [README](../README.md)의
"📐 가격행동 전략" 절에 있고, 이 문서는 **왜 이렇게 만들었는지, 무엇을 검증했고
무엇이 아직 확인되지 않았는지**를 남긴다.

---

## 1. 결론 요약

- 책의 규칙 5개를 그대로 쓰면 업비트에서 **비용(왕복 0.12%)을 넘지 못한다**
  (180일 백테스트, 986건, 평균 −0.064%).
- **추세 캥거루 + ladder 청산**만 뚜렷하게 양수였다 (109건, 평균 +0.92%, PF 2.05).
  전반·후반 90일 모두 24개 조합 중 1등이었다.
- 하지만 이 수익은 **큰 승리 5건에 몰려 있다** (그 5건을 빼면 −0.02%).
  **DSR 0.37 · PBO 0.65**로 운과 구분되지 않는다.
- 그래서 라이브 기본값은 이 후보로 두되, **실주문은 검증 게이트가 막는다.**
  봇이 매일 스스로 재평가하고, 표본 외 종이 매매가 쌓여 기준을 넘으면 그때
  열린다. 넘지 못하면 영원히 종이 매매만 한다.

## 2. "알트 급등을 잡으면 수익률이 오르나?"에 대한 답

**급등 추격은 넣지 않았다.** 이유는 두 가지다.

1. 책은 돌파 대부분을 가짜 돌파로 본다. 추격 매수는 책의 방식과 반대다.
2. 업비트 급등 알트 상당수는 업비트가 '주의'(가격 급변·거래량 급증·입금 급증·
   해외 괴리·소수계정 집중)로 지정한 펌프다.

대신 **"급등 뒤 첫 쉬어가기/되돌림"**을 패턴으로 잡는다 (추세 캥거루·라스트 키스).
알트는 거래대금·호가가 두껍고 경고가 없는 종목만 고른다 (`AltUniverse`).

결과적으로 알트가 수익 대부분을 냈다: 추세 캥거루 기준 알트 +1.02% (94건) vs
코어 +0.32% (15건). 다만 알트 유니버스를 '지금' 상위 종목으로 골랐으므로
**생존자 편향**이 있다.

## 3. 구조

| 파일 | 역할 |
|---|---|
| `price_action.py` | 존·패턴 판정. 순수 함수, 라이브와 백테스트가 같은 코드를 쓴다 |
| `candle_feed.py` | 업비트 캔들 캐시(마감 봉만), 과거 수집, 알트 유니버스 선별 |
| `naked_strategy.py` | `Trade` 상태기계, `PaperBook` 종이 장부, `NakedStrategy` 라이브 연결 |
| `validate_naked.py` | 백테스트, DSR/PBO 평가, 실주문 게이트, 자동 검증 |
| `meta_trainer.py` | `NakedMetaTrainer` — 패턴 신호 전용 메타 모델 |
| `main.py` | 전략 모드, 진입 필터(뉴스·메타·서킷브레이커), 게이트 적용, 스케줄 |
| `execution_engine.py` | 알트 동적 구독(`watch`/`unwatch`), 긴급 청산 |

```
1시간봉 마감 → 4시간봉 존 → 패턴 판정 ─┬→ 종이 매매 (모든 신호 × 청산 4종)
                                      └→ 라이브 패턴이면: 필터 → 매수스톱 대기
                                               ↓ (웹소켓 틱으로 돌파 확인)
                시장가 매수 → 손절(꼬리 아래) / 목표(다음 존) / 추적 → 시장가 매도
```

**종이 매매와 라이브를 둘 다 두는 이유:** 라이브 체결은 필터를 거쳐 표본이
치우친다. 전략 자체의 성과는 필터와 무관하게 모든 신호로 재야 검증이 성립한다.

## 4. 책 → 코드

| 책 | 코드 | 숫자로 옮긴 규칙 |
|---|---|---|
| 4장 존 | `find_zones` | 4시간봉 **종가** 꺾임 3회 이상, 0.5 ATR 안은 한 존, 극단 고저점은 1회도 인정 |
| 5장 라스트 키스 | `last_kiss` | 20~60봉 박스(높이 1.5~8 ATR, 상하 각 2회 터치) 돌파 후 상단 되돌림 양봉. 종가가 박스 안이면 즉시 청산 |
| 6장 빅 섀도 | `big_shadow` | 감싸기 + 종가 위쪽 25% + 직전 5봉 최대 + 왼쪽 여백 7봉 |
| 7장 와미/물라 | `wammie` | 이중바닥, 두 번째 저점이 더 높고 6봉 이상 간격, 사이에 1 ATR 이상 이탈 |
| 8장 캥거루 꼬리 | `kangaroo_tail` | 시가·종가 위쪽 1/3, 직전 봉 범위 안, 직전 3봉보다 큼, 1 ATR 이상, 존 + 여백 7봉 |
| 9장 빅 벨트 | — | **제외** — 주말 갭 전제인데 코인은 24시간이라 갭이 없다 |
| 10장 추세 캥거루 | `trendy_kangaroo` | 40봉 추세(3 ATR, R² 0.5) 중 3~10봉 쉬어가기, 꼬리가 쉬어가기 저점 아래로 |
| 11장 청산 | `Trade` | zone(존 없으면 3봉 추적) / split / ladder / three_bar |
| 13장 반대 신호 | `EXIT_ONLY` | 저항 존의 약세 캥거루·빅섀도·물라 → 보유분 청산 |

- 현물이라 공매도가 없다. 매도 패턴은 청산 신호로만 쓴다.
- 진입은 전부 **매수스톱**(신호 봉 고가 + 0.05 ATR). 돌파 전에 손절선부터 닿으면
  신호를 버린다 (13장). 유효기간 2봉.
- 손절폭이 0.24% 미만(비용이 손익을 지배)이거나 8% 초과면 신호를 버린다.
- 사이징은 고정 위험: 손절 시 `NAKED_RISK_PER_TRADE_KRW`(기본 1,000원)를 잃도록,
  **실제 매수 시점 가격** 기준으로 금액을 정한다.
- 종이 매매의 봉 안 경로 가정은 보수적이다: 같은 봉 진입+손절 → 손실, 같은 봉
  손절+목표 → 손절, 진입 봉에서는 목표 불인정, 갭 하락 → 시가 청산.

## 5. 검증 체계

### 게이트 기준 (실주문 모드에서만)

- 라이브 설정(패턴 × 청산) 거래 100건 이상, 비용 후 평균 > 0
- DSR ≥ 0.95 — 시행 수는 비교한 조합 전부(청산 4 × (패턴 5 + 전체) = 24)
- PBO ≤ 0.5 — 같은 24개 조합의 일간 수익으로 CSCV
- 표본 외 종이 매매 30건 이상, 평균 > 0
- 리포트가 **현재 라이브 설정**을 평가한 것 + 3일 이내

### 자동 검증 (`NAKED_AUTO_VALIDATE`)

- 기동 시 + 하루 한 번: 백테스트 거래 + 쌓인 종이 매매를 합쳐 재평가.
- 백테스트가 30일보다 오래됐거나, 결과를 바꾸는 설정(패턴·손익비·유효 봉 수·
  보유 기한·봉 단위·존 봉 수·청산방식 목록)이 바뀌면 백그라운드에서 새로 돌린다
  (약 5분).
- 캔들 요청은 라이브 스캔 초당 6회 + 자동 백테스트 초당 3회로 나눠 업비트 시세
  한도(초당 10회)를 넘지 않는다. 백테스트 계산은 스레드에서 돌아 매매를 막지 않는다.
- 게이트는 닫혔다가 다시 열릴 수 있고, 바뀔 때 텔레그램으로 알린다. 닫히면
  대기 매수스톱만 취소하고 보유 거래는 끝까지 관리한다.

### 표본 일치 원칙

- 종이 장부는 **종목 × 청산방식 × 패턴마다** 거래 하나씩 굴린다. 패턴끼리 막으면
  다른 패턴 종이 거래 때문에 라이브 패턴 신호가 빠져, 실제 운용과 다른 표본이 된다.
- 여러 패턴을 함께 쓰는 조합은 평가 때 `non_overlap`이 라이브의 '종목당 1거래'
  규칙을 적용한다 (보유 중·매수스톱 대기 중 모두 점유).

## 6. 백테스트 결과 (2026-09-24, 180일, 1시간봉, 코어 4 + 알트 20)

| 구성 | 거래 | 승률 | 평균(비용 후) | PF |
|---|---:|---:|---:|---:|
| 책 규칙 5개 전체, zone 청산 | 986 | 33.6% | −0.064% | 0.94 |
| 같은 신호, ladder 청산 | 949 | 29.6% | +0.072% | 1.07 |
| 캥거루 꼬리 (zone) | 160 | 31.2% | −0.081% | 0.92 |
| 빅 섀도 (zone) | 173 | 33.5% | −0.371% | 0.69 |
| 와미 (zone) | 573 | 35.2% | −0.120% | 0.89 |
| 라스트 키스 (zone / ladder) | 111 / 110 | 27.9% / 24.6% | +0.212% / +0.408% | 1.18 / 1.35 |
| **추세 캥거루 (ladder)** | **109** | 27.5% | **+0.924%** | 2.05 |

추세 캥거루(ladder) 세부:

| 구분 | 값 |
|---|---|
| 전반 90일 / 후반 90일 | +0.23% (50건) / +1.51% (59건) |
| 30일 구간 6개 | +0.42 / +0.57 / **−0.42 / −0.48** / +2.94 / +1.36% |
| 알트 / 코어 | +1.02% (94건) / +0.32% (15건) |
| 상위 5건(+12~26%) 제외 | **−0.02%** |
| 청산 사유 | 손절 94 · 반대 신호 14 · 기한 1 |
| 매수스톱 체결률 | 67% |
| DSR / PBO | **0.37 / 0.65** (둘 다 기준 미달) |

해석:

- 비용 전 평균 +0.06% — 책 규칙 그대로는 왕복 0.12%를 못 넘는다.
- 반전 패턴(캥거루 꼬리·빅 섀도·와미)은 음수, 추세 쪽(추세 캥거루·라스트 키스)만 양수.
- 추세 캥거루는 전형적인 추세추종 분포(낮은 승률, 소수의 큰 승리)다. 진짜 엣지일
  수도 있지만 표본 110건으로는 운과 구분할 수 없다.
- 가격행동 메타 모델은 CV AUC 0.54로 기준(0.55) 미달이라 필터로 쓰지 않는다.
- **이전 수치는 무효:** 첫 실행(79건, PBO 0.17)은 종이 장부가 패턴끼리 서로
  막던 버그 때문에 추세 캥거루 30건가량이 빠진 결과였다.

## 7. 최종 검증에서 찾아 고친 문제

세 차례 전체 점검(+ 추가 점검 1회)에서 찾은 것. 모두 수정했고 대부분 스모크
테스트로 고정했다.

### 돈이 걸린 문제

| # | 문제 | 수정 |
|---|---|---|
| 1 | 클럭이 30초 넘은 작업을 취소하는데, 주문 접수 후 알림 대기 중 취소되면 거래가 '미체결'로 남아 **다음 틱에 같은 매수를 또 낸다** | 주문~상태 반영 구간을 `asyncio.shield`로 보호, 종목 간은 순차 처리 (수정 전 코드에서 테스트가 매수 2회를 재현함) |
| 2 | 종료 시 엔진이 거래소 연결을 먼저 닫고 상태를 저장 → 진행 중 매수가 기록 안 된 채 재시작하면 재매수 | 종료 절차에서 가격행동 틱을 먼저 멈추고 진행 중 주문을 최대 20초 기다린 뒤 엔진 종료 |
| 3 | 매수 응답 대기 중 봉 마감 스캔이 그 거래를 만료 처리 → 체결된 포지션이 추적에서 빠진 **손절 없는 고아** | 주문 처리 중(`busy`)인 거래는 스캔이 건드리지 않음 |
| 4 | 재시작 후 밀린 봉을 재생할 때 **옛 신호로 주문** | 방금 마감된 봉의 신호만 주문, 재생 봉은 종이 매매만 |
| 5 | 재시작 때 복원된 대기 매수스톱이 게이트가 닫혀 있어도 체결 | 게이트가 닫히면 대기 매수스톱 취소 (`live_disabled`) |
| 6 | 사이징을 신호 진입가로 계산 → 갭·지연으로 비싸게 사면 손실이 1회 한도 초과 | 실제 매수 시점 가격으로 계산 |
| 7 | 매수 직후 손절이면 잔고 캐시(15초)에 체결분이 없어 '미보유'로 거부 | 긴급 청산인데 보유 0이면 잔고 즉시 재조회 |
| 8 | 실주문 재시작 시 미체결 주문 복구가 코어만 보고 알트 누락 | 추적 중인 알트까지 복구 |
| 9 | 모의 모드 재시작 시 모의 장부 초기화로 보유 거래 청산이 계속 거부 | 복원된 보유 거래를 모의 장부에 다시 얹음 |
| 10 | 라이브 거래 중인 알트가 유니버스에서 빠지면 봉 마감 청산(기한·반대 신호·추적)을 못 받음 | 라이브·종이 거래가 남은 종목은 계속 스캔 |

| 17 | 백테스트가 이벤트 루프를 막고, 라이브 스캔과 합쳐 조회 한도 초과 가능 | 계산은 스레드, 요청 속도 6 + 3회/초로 분리 |
| 18 | 거래 없는 종목에 20초마다 캔들 재요청 | 최소 30초 간격 |
| 19 | 텔레그램이 느리면 다른 종목 손절 감시 지연 | 가격행동 알림은 기다리지 않음 |
| 20 | 웹소켓 재구독 시 닫기 태스크 참조가 없어 GC로 사라질 수 있음 | 참조 보관 |
| 21 | 존 봉 수 > 200(업비트 1회 한도)이면 라이브와 백테스트가 다른 존을 그림, 잘못된 봉 단위 허용 | 설정 검증에서 차단 |

### 문제없음을 확인한 부분

- 패턴 판정에 미래 봉 참조 경로가 없다. 피벗은 좌우 3봉이 모두 마감된 것만,
  상위 시간봉은 판정 시각까지 마감된 봉만 쓴다.
- 가격행동 포지션을 다른 경로(LLM 판정, 서킷브레이커)가 파는 곳이 없다.
  `STRATEGY_MODE=naked`에서 LLM 판정은 기록만 한다.
- 리스크 한도(종목당·전체 노출·일손실·일일 매수 수)와 가격행동 청산이 충돌하지
  않는다. 손절·목표 청산은 `urgent=True`로 재주문 쿨다운만 건너뛴다.
- 백테스트가 백그라운드에서 도는 동안에도 클럭 틱이 초당 1회로 유지됐다
  (DRY-RUN 실측).

## 8. 테스트

`python smoke_test.py` — 오프라인, 네트워크 없음, **223개 전부 통과**.
가격행동 관련 절:

- [11] 패턴 판정 (합성 봉으로 각 패턴의 참/거짓 조건)
- [12] 거래 상태기계 (매수스톱, 보수적 체결, 11장 청산 4종, 직렬화)
- [13] 라이브 연결 (매수스톱 → 매수, 고정 위험 사이징, 손절, 알트 구독/해제, 재시작 복원, 서킷브레이커)
- [14] 부대설비 (마감 봉 처리, 알트 선별, 긴급 청산, 동적 구독, 게이트)
- [15] 최종 검토 수정분 (위 표의 1·2·3·4·5·6·10·11·13·14·15·16·18번 등)

실데이터 확인: 180일 백테스트(업비트 공개 API), DRY-RUN 실기동 2회(110초·120초,

## 10. 실주문 전환 절차

1. DRY-RUN으로 상주시키며 종이 매매를 쌓는다 (게이트가 요구하는 표본 외 증거).
2. 로그의 `가격행동 검증:` 줄이나 `state/naked_validation.json`에서 판정을 본다.
3. **PASSED가 뜨기 전에는 실주문을 켜지 않는다.** 게이트가 막긴 하지만
   `NAKED_REQUIRE_VALIDATION=false`로 우회하지 말 것.
4. 통과하면 별도 계정·소액으로 `DRY_RUN=false` + `NAKED_LIVE=true`.
   알트까지 하려면 `NAKED_LIVE_ALTS=true`.
5. 표본 외에서 무너지면(게이트가 다시 닫히면) 기본 후보(추세 캥거루)를 버리고
   다시 검토한다.

수동 확인이 필요하면: `python validate_naked.py report --state-dir <봇 상태 폴더>`
(서버는 `/var/lib/coinbot`).

## 11. 남은 한계

- **손절은 봇이 감시한다.** 업비트 현물에 스톱 주문이 없다. 봇이 멈추거나 시세가
  30초 이상 끊기면 그동안 손절이 나가지 않는다. 급락 중에는 손절가보다 불리하게
  체결된다.
- **뉴스 거부권은 코어 4종목에만 걸린다.** 라이브 거래 대부분인 알트는 뉴스 필터
  없이 들어간다 (알트까지 LLM을 부르면 비용 약 6배).
- **라이브 기록의 체결가는 주문 직전 최신 체결가**다. 실제 평균 체결가가 아니라
  라이브 수익률이 약간 낙관적이고, 매도 수량도 추정치(엔진이 보유량으로 자름)다.
- **LLM 시절부터 보유한 코어 코인은 가격행동이 관리하지 않는다.**
- **알트 백테스트는 생존자 편향**이 있다.
- **표본 외 종이 매매 30건은 약한 증거**다. 이 전략처럼 수익이 소수 거래에 몰리면
  30건 평균은 운에 크게 흔들린다. 실질적 관문은 DSR·PBO다.
- **시장가 슬리피지는 왕복 0.12% 안에만** 반영됐다. 호가가 얇은 알트는 더 크다.
- 가격행동 모드에서도 Gemini 호출은 계속된다 (뉴스 거부권·기록용).
  비용을 줄이려면 `config.py`의 `LLM_INTERVAL_SEC`를 늘린다.
- 업비트가 상장폐지·거래정지한 알트를 들고 있으면 시세가 끊겨 청산하지 못할 수 있다.
